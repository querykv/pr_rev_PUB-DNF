# Advisories rejected by hand during curation of the labelled corpus.
#
# The automated rules in `benchmark/ghsa.py` reject what can be decided
# mechanically: no CWE, no fixing commit, a merge parent, a diff too large to
# read, a fix touching no reviewable Python, a span that is entirely imports or
# a version bump. What they cannot decide is whether the ground-truth spans
# actually *localize* the vulnerability. That needs somebody to read the diff,
# and the outcome lands here.
#
# Applied with `--exclude`, so the corpus stays rebuildable from the same
# command. Editing `labelled.json` directly would be the obvious alternative and
# would destroy exactly that.
#
# Format: `GHSA-id` or `owner/repo@sha`, then `# reason`.
#
# Prefer the commit form when the commit is what is unusable. Excluding by
# advisory id alone was tried first and leaked: several advisories can share one
# fixing commit, so rejecting one id freed a per-repo slot that the next id on
# the same commit walked straight into. These two commits came back under four
# GHSA ids between them.
#
# ---------------------------------------------------------------------------
